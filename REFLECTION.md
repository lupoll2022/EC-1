Git is very useful in work with modeling workflows due to its abilit to keep track of changes in code,
 which allows for a simple way to recover earlier versions. Through branches, you are able to test
 changes without having any impact on the main version of the project. Another thing I learned that
 merge conflicts occur if a branch changes the same part of a file as another branch, and git allows
 for a simple way to manually resolve this. Another thing I learned was that Git is able to recover
 files after you commit a bad edit or even an accidental deletion, which is useful when working on
 modeling code. Lastly I learned that using .gitignore is able to keep large data files and generated
 outputs out of the repository, which is what should ussualy be done.
